# Журнал посещений

Свой счётчик вместо Метрики: страница шлёт событие в Cloudflare Worker,
тот пишет строку в базу D1. Ни кук, ни сторонних скриптов, сырой IP не
сохраняется — вместо него суточный анонимный хеш.

## Что считается

| Событие | Когда |
|---|---|
| `pageview` | открытие страницы |
| `click_telegram` | клик по любой кнопке связи |
| `promo_click` | клик по кнопке в блоке акции |
| `demo_play` | переключение вкладки с роликом |
| `calc_used` | первое движение ползунка калькулятора |
| `form_submit` | форма успешно отправлена |

У каждой строки есть отметка `src`: `web` или `telegram`. Внутри
мини-приложения `document.referrer` пуст, поэтому источник помечается
отдельно — иначе такие заходы слились бы с прямыми.

## Разворачивание

Node и npm на машине есть, wrangler ставится вместе с командой.

```bash
cd ~/Desktop/код/avtomatizacia/analytics && npx wrangler login
```

Создать базу — команда напечатает `database_id`, его нужно вписать в `wrangler.toml`:

```bash
npx wrangler d1 create inertia-log
```

Создать таблицу:

```bash
npx wrangler d1 execute inertia-log --remote --file=schema.sql
```

Задать два секрета: `STATS_KEY` — пароль к сводке, `HASH_SALT` — любая
длинная случайная строка для хеша посетителя:

```bash
npx wrangler secret put STATS_KEY
```

```bash
npx wrangler secret put HASH_SALT
```

Выложить:

```bash
npx wrangler deploy
```

Команда напечатает адрес вида `https://inertia-log.ваш-поддомен.workers.dev`.
Его нужно вписать в `js/stats.js` в переменную `ENDPOINT` — до этого файл
молчит и никуда не ходит.

## Сводка

Открывается по адресу воркера:

```
https://inertia-log.ваш-поддомен.workers.dev/stats?key=ВАШ_STATS_KEY
```

Показывает по дням просмотры, посетителей, клики в Telegram и заявки,
разбивку по событиям, откуда открывали (сайт или приложение) и источники
перехода. Период меняется параметром `&days=90`.

## Заявки с формы в Telegram

Тот же воркер принимает форму на `POST /lead`, кладёт заявку в базу и
отправляет её ботом в ваш чат. Токен бота живёт секретом Cloudflare и в
репозиторий не попадает.

Сначала напишите боту `/start` с того аккаунта, куда должны приходить
заявки — иначе бот не имеет права вам писать.

Задайте токен бота:

```bash
npx wrangler secret put TG_BOT_TOKEN
```

Узнайте свой `chat_id` — откройте в браузере адрес воркера с ключом:

```
https://inertia-log.ваш-поддомен.workers.dev/chatid?key=ВАШ_STATS_KEY
```

Страница покажет список тех, кто писал боту, с их идентификаторами.
Нужный положите в секрет:

```bash
npx wrangler secret put TG_CHAT_ID
```

После этого выложите воркер заново: `npx wrangler deploy`.

Заявка сохраняется в базу **в любом случае** — даже если Telegram недоступен
или секреты не заданы. Последние пятьдесят заявок видны в сводке первой
таблицей, там же колонка «в_telegram» показывает, дошло ли сообщение.

Защита от спама: скрытое поле-приманка (боты его заполняют, люди нет) и
ограничение — не больше трёх заявок с одного отпечатка за десять минут.

## Ограничения

- Бесплатный тариф D1: 5 ГБ и 5 млн чтений строк в сутки. Для этого сайта
  запас на годы.
- Блокировщики рекламы этот запрос обычно не режут: домен свой, имён вроде
  `analytics` в пути нет.
- В `worker.js` список `ALLOWED_ORIGINS` ограничивает, с каких доменов
  принимаются события. При смене адреса сайта его нужно поправить.
- Сводка не считает отказы и время на странице — для этого нужен полноценный
  счётчик. Здесь только журнал событий.
